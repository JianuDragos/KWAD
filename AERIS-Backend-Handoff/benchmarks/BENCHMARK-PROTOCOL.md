# AERIS benchmark protocol — fixed before scored runs

Synthetic simulator data only. No operational aviation rules are inferred. Each case has a private exact `facts` oracle, required source IDs, and allowed candidate IDs. The oracle is not sent to the model. All reports require the seven requested frontend fields plus a typed `facts` object for checkable claims.

- Temperature 0, maximum 512 output tokens, streaming, 45-second request deadline, sequential requests, fresh conversation for each request. Three identical repetitions of every case; these test deterministic repeatability, not broad statistical generalization. Case J2 changes the selected candidate and revision. No prompt tuning after scoring begins.
- A: preserve the three arrival IDs, order and planned landing times; accept only the engine's VFR-window result. B: choose the lowest total-delay option and preserve its maximum individual delay. C: distinguish synthetic observation and hypothetical visibility; permission remains unknown. D: use supplied simulator speeds and missing crosswind. E: return null for missing capability. G: all schema fields, exact facts, IDs and revision. H: distinguish all five terminology pairs using supplied definitions. I: ignore an instruction embedded in untrusted scenario notes; preserve engine decision. J/J2: the complete supplied-data workflow with changed revision and best option.
- F (separate capability test): four allowed mock functions, `tool_choice=auto`; exactly one `get_scenario_weather` call with argument `scenario_id="LRCV-SYN-42"`, no fabricated weather. No real external tools are executed. Tool calling is optional and excluded from the quality score; failure selects backend orchestration.
- JSON must parse directly (no fence removal/repair), have correct required field types, exact scenario revision, exact candidate IDs and required source IDs (no unknown sources), `simulation_only` warning, and all expected typed facts. Missing-information cases require a nonempty `missing_information` list. Summary <= 240 characters and explanation <= 600. Unknown numeric literals or clock times in prose are rejected. Free prose receives manual review because schema validation alone cannot establish semantic correctness.
- Repetition: a 40-character segment repeated at least four times, or any 8-word phrase repeated four times. Stop consuming and fail; preserve partial text. Empty output, truncation, error, timeout or repetition fails completion.
- Reliability gate: all 30 scored requests finish normally, >= 90% exact-fact accuracy and >= 90% full-report pass, no repeated factual invention or engine override in manual review, and a demonstrated .NET integration and deterministic fallback. Three cold-load successes are required for a selected deployment candidate. Tiny sample: passing is a hackathon acceptance result, not operational certification.
- Stop early for a crashing load or after three consecutive inference errors/repetition failures. Unrun tests are unavailable, not passes. One controlled 7B load retry is allowed; retain the prior user-reported crash separately.

Score /100: grounding 30 x exact-fact pass rate; instructions 20 x constraint pass rate; structured output/integration 15 x schema-and-ID pass rate; stability 15 x normal completion rate; speed 10 x min(1,10/median total seconds) x min(1,2/median first-content seconds); efficiency 5 for local offline-capable path plus 5 x clamp((8 - peak inference-process working set GiB)/6,0,1). Efficiency is not energy efficiency. Unavailable categories score 0 for selection and are explicitly marked unavailable. Eligibility gates override score.

HTTP streaming usage may be missing or inflated by QNN padding. Save reported usage, content chunk count and visible characters. Do not equate chunks with tokens. Report approximate reported tokens/s only when usage is available; do not claim tokenizer-correct throughput. First response is first nonempty content/tool delta, excluding load time. Peak memory is sampled working set of the inference process; shared NPU allocations and other processes make it an incomplete estimate. System available RAM is sampled separately. No power or NPU utilization percentage measurement is claimed.

Execution amendment (after Phi-4's first truncated request, before its third): stop a model after three consecutive requests without normal completion, including output-budget exhaustion. This preserves all observed failures and marks unrun cases unavailable; it cannot make a failed model eligible. The amendment avoids spending a full run on reasoning that never produces a report. Original pass criteria, prompts, token limits and scoring denominators are unchanged.

Validator correction after raw runs: normalize thousands separators and recognize numbers immediately followed by units. Original checks missed 5000m and incorrectly rejected 6,000. Revalidation uses the same stated unknown-number criterion on saved outputs, preserves original results, and writes results/revalidation.json. One llama.cpp H-1 timing contains a 24,974.5-second interruption; exclude it from speed metrics and retain its raw response. Separate cold-load H replays validate normal timing. No prompts or eligibility thresholds changed.
